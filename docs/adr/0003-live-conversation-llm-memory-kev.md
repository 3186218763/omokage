# ADR 0003：以 Turn Coordinator 统一 LLM、记忆与 Kev 的实时对话生命周期

- 状态：已接受设计方向
- 日期：2026-09-24

## 背景

项目已有 LLM 流式生成、SQLite 会话与用户记忆、Kev 表演判定、TTS 预取和 Live2D 播放逻辑，但这些能力由不同层分别编排。实时对话最容易出现的错误是旧轮迟到事件污染新轮、未播放文本写入记忆、Kev 或摘要阻塞首句，以及前端按网络事件顺序猜测播放状态。

## 决策

引入一个 `LiveConversation` 深模块作为唯一的轮级协调器。它拥有 `Turn` 生命周期和事件协议；LLM、记忆、Kev、TTS 和播放系统通过适配器连接。每轮使用 `turn_id + generation` 做失效检查，所有外部效果以句子播放回执结算。

记忆采用 Persona、Character facts、User memory、Conversation 四层模型。用户长期记忆只能从已提交且可追溯的用户原话产生；摘要不产生长期事实。Kev 每轮最多一次，只返回轮级表演情绪建议，无法使用时回落到 LLM 说话语气。

## 取舍

这会让协调器成为较深的模块，内部需要维护任务取消、句子顺序和事务提交；换来的收益是 Web 路由、React hook 和供应商适配器不再重复实现生命周期规则。首句判定只使用台词前缀，可能比等待整轮文本更早但不够稳定；这是为了 live 延迟选择的明确取舍。SQLite 先承担本地真相源，向量检索延后到关键词检索无法满足真实语料时再引入。

## 后果

未来替换 LLM、Kev、TTS 或记忆检索实现时，领域事件和播放协议保持不变。实现必须先完成轮级身份、取消和提交语义，再扩展更复杂的模型、动画或全双工能力。
