# P1-8 时间感知：她知道今天几号、现在几点

**状态（2026-09-24）：改进方案已在 `232b7c6`，本篇移入 `done/`。** `dialogue/memory.py` 组 prompt 时注入当天日期与 `[HH:MM]` 前缀，前缀不落历史；`dialogue/conversation.py` 保存每条消息的本地时间，摘要输入也附时间。仍需用真实会话核对跨天表达，并跑既有人设盲测。时区处理按原方案不做。

## 差距（airi 怎么做）

airi 的时间注入细节（值得照抄的 KV-cache 友好设计）：**系统提示锚定「今天」的日期**（一天内稳定，不击穿前缀缓存），每条消息带 `[HH:MM]` 时间前缀（每轮自然变化，不动 system prompt）——角色知道时间流逝，又不为它付缓存失效的代价。

## 我们的现状

实施前 `prepare_chat_messages` 不含时间信息；当前代码已有日期和历史消息时间，但**只在生成回复时组装上下文**，长时间停在同一轮不能给模型实时更新时钟。

## 改进方案

1. **日期锚点**：system prompt 末尾追加一行 `今天是 YYYY-MM-DD 星期X。`（`get_system_prompt()` 拼装处，persona.py 的稳定部分不动，日期在 `prepare_chat_messages` 时追加，同一天内字节级不变）。
2. **消息时间前缀**：近 8 轮原文的 user/assistant 消息内容前缀 `[HH:MM]`（落库与历史存储不带前缀，只在组 prompt 时加，避免污染 `conversation.py` 的原文语义）。
3. 摘要 prompt（`llm_client.summarize_chat`）同步带上时间范围，压缩历史时保留「那晚/上周」级别的时间感。

不做：倒计时、时区处理（单用户本地时区 `datetime.now()` 即可）、节假日表（可后补，如「今天是你的生日」这类锚点留给 P2-11）。

## 验收

- 单测：同一天内两次组 prompt 的 system 部分逐字节相同（KV-cache 友好性）；跨天变化；消息前缀不落历史。
- 盲测：问「现在几点/今天几号」答对；长对话里出现与真实时长一致的「聊了好久」类表达（加分项，非硬性）。

## 边界与风险

- 改动极小但触 prompt：跑一遍既有 eval-set（T2 盲测集）确认文本语气指纹无漂移。
- 时间前缀会轻微增加 token 量（每条 7 个左右），可忽略。
